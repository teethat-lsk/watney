# 0001 — คิดค่าน้ำตามมาตรน้ำ (Metered billing only)

- **Status:** Accepted
- **Date:** 2026-10-16

## Context

ประปาหมู่บ้านในไทยไม่มีอัตรากลางของประเทศ แต่ละแห่งกำหนดเองผ่านคณะกรรมการ/ข้อบัญญัติ อปท. รูปแบบที่พบทั้งหมดคิดจาก **หน่วยที่ใช้ตามมาตร (ลบ.ม.)** ต่างกันแค่วิธีคิดราคาต่อหน่วย และค่าบริการคงที่ที่บวกเพิ่ม — ดู [research §2.2](../research/village-water-billing-thailand.md) หมู่บ้านเป้าหมายของ Watney ก็คิดตามมาตรน้ำ

## Decision

1. **ทุกบิลค่าน้ำคำนวณจากเลขมาตร** — `units = current − previous` แล้วนำไปคิดราคาตาม tariff ไม่รองรับผู้ใช้น้ำแบบเหมาจ่ายที่ไม่มีมาตร ผู้ใช้น้ำทุกรายต้องผูกกับมาตร
2. **Tariff เป็น config ต่อระบบประปา และ versioned ตามวันมีผล** (ไม่ hard-code อัตรา) รองรับ:
   - **อัตราเดียว** — `units × rate` (เช่น 7 บาท/ลบ.ม.)
   - **ขั้นบันได (incremental blocks)** — แต่ละช่วงหน่วยคิดราคาของช่วงนั้น (เช่น 1–80 = 3, 81–150 = 5, 151+ = 8 บาท)
   - **ค่ารักษามาตร/ค่าบริการรายเดือน** — บวกเพิ่มทุกบิล เก็บแม้ใช้ 0 หน่วย อาจต่างกันตามขนาดมาตร
   - **ค่าน้ำขั้นต่ำ** (optional) — ถ้าค่าน้ำต่ำกว่าเกณฑ์ ให้คิดเท่าเกณฑ์
   - **กฎปัดเศษหน่วย** (เช่น เศษ ลบ.ม. ปัดขึ้น)
3. **ข้อยกเว้นเดียวที่ไม่ใช้เลขมาตรจริง: มาตรเสีย/อ่านไม่ได้** — บันทึกเป็นการอ่านแบบประมาณการ (`estimated`) พร้อมเหตุผลและผู้อนุมัติ วิธีประมาณเป็น config ต่อระบบ (เฉลี่ย 3 รอบ หรือคิดอัตราเหมาต่อบิล) และต้องแยกให้เห็นในรายงาน
4. ค่าธรรมเนียมที่ไม่เกี่ยวกับการใช้น้ำ (ค่าติดตั้งมาตร ค่าต่อน้ำ ค่าปรับ ฯลฯ) อยู่ใน fee schedule แยก ไม่ใช่ส่วนของ tariff

ตัวอย่าง: previous = 100, current = 150, อัตราเดียว 6 บาท + ค่ารักษามาตร 10 บาท → 50 หน่วย, 310 บาท (ตรงกับตัวอย่างทดสอบใน MVP spec issue #1)

## Consequences

- Billing domain service รับ input `(previous, current, tariff_version)` อย่างเดียว ไม่มี code path แบบเหมาจ่าย — ทดสอบง่าย
- ต้องมี **ทะเบียนมาตร** (หมายเลข, ขนาด, วันติดตั้ง, ประวัติเปลี่ยนมาตรพร้อมเลขเริ่มต้นใหม่) เพราะการคิดเงินพึ่งมาตรทั้งหมด และค่ารักษามาตรอาจขึ้นกับขนาด
- การเปลี่ยนมาตรกลางรอบต้องคิดหน่วยจากมาตรเก่า (ถึงเลขสุดท้าย) + มาตรใหม่ (จากเลขเริ่มต้น)
- บิลเก่าต้องอ้าง `tariff_version` ที่ใช้คิด เพื่อให้คำนวณซ้ำ/ตรวจสอบย้อนหลังได้เมื่อเปลี่ยนอัตรา
- อัตราจริงของหมู่บ้านเป้าหมายยังไม่ได้ระบุ — ตั้งค่าตอน onboarding ตัวเลขใน research ใช้เป็น test fixtures เท่านั้น
